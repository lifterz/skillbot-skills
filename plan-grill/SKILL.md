# Plan Grill · 需求打磨

一句话想法 → 五轮追问 → 可执行需求。不接受模糊，替用户想清楚再动手。

## 何时使用

- 用户的需求描述只有一句话或一段情绪
- 动手写代码 / 写方案之前，需要确认"到底要做什么"
- 用户说"你看着办"但方向影响后续大量工作

## 工作流

### 第 1 步：复述 + 挑明假设
用一句话复述你听到的需求，然后列出 2-3 个你脑中冒出的理解分歧点。

### 第 2 步：五轮关键追问（每轮一个问题，等用户回答）
1. **目标用户** —— 谁用？多频繁？付费的还是免费的？
2. **核心闭环** —— 用户完成什么动作算"用成了"？一步说清。
3. **现实承接** —— 线下/外部环节谁来干？干不了怎么办？
4. **定价模式** —— 谁付钱？为什么现在付？
5. **MVP 边界** —— 第一版砍到什么程度还能成立？

追问规则：一次只问一个；选项化（给出 A/B/C 降低回答成本）；用户答"都行"时替他选一个并说明理由。

### 第 3 步：装配需求卡
追问完成后输出固定四件套：

```
【目标】一句话
【用户画像】2-3 条，含频次
【MVP 范围】做 / 不做 清单（"不做"和"做"同样重要）
【成功指标】1 个北极星指标 + 2 个护栏指标，含具体数字
```

### 第 4 步：风险预埋
列出 2 个最可能翻车的点，各配一个"翻车时怎么办"。

## 质量检查

- [ ] 每个追问都是选项化提问，用户可以一个字回答
- [ ] MVP 范围里有至少 2 条明确的"不做"
- [ ] 成功指标有数字和截止时间，不是"提升用户体验"
- [ ] 全程没有出现"赋能""抓手""闭环生态"这类空话

## 输出格式

需求卡（Markdown）+ 风险清单。如果用户中途给出新信息，回头修订已确定的条目，而不是追加到末尾。
