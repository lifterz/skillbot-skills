# Bug Hunter · Bug 诊断

现象 → 假设树 → 排除法 → 根因 → 验证。治诊断拖延症：先定位，再动手。

## 何时使用

- 偶现、难复现的 Bug
- 多个可能原因并存，不知道从哪查起
- "昨天还好好的"类回归
- 性能突然劣化

## 工作流

### 第 1 步：取证（不猜）
- 错误日志全文、时间线（何时开始、频率、有无规律如整点/发版后）
- 影响面：全量还是部分用户？哪个路径？
- 最近变更：发版、配置、依赖、上游服务
**没有证据之前，所有"我觉得是"都只是待验证假设。**

### 第 2 步：建假设树
列出 3-5 个候选根因，每个标注：
- 初始置信度（%）
- **验证方法**（能证伪它的一个具体检查，如查某段时间的网关超时率）

假设必须可证伪。"可能是缓存问题"不算——"清掉缓存 X 后错误率归零才算"才算。

### 第 3 步：逐个排除
按"验证成本从低到高"排序执行，每完成一个验证更新置信度：
- 排除 → 划掉并记录证据
- 确认 → 停止排查，进入修复

### 第 4 步：根因修复
- 修根因，不修症状（偶发问题加 retry 前先回答"为什么会偶发"）
- 补丁 + 一条能稳定触发的复现测试（没有复现测试的偶现 Bug 修复不算完成）

### 第 5 步：回归验证
跑全量相关测试；上线后按原指标观察一个观察窗（如 24h 错误率）。

## 质量检查

- [ ] 每个假设都有明确的证伪检查
- [ ] 结论有证据链，不是"大概率是"
- [ ] 修复附带稳定复现测试
- [ ] 顺带回答了"为什么之前没炸"

## 输出格式

根因一句话 → 证据链 → 补丁 → 回归结果。诊断过程（假设树）折叠附后供复查。
