# Task Splitter · 任务拆解

大目标 → 依赖图 → 工单 → 关键路径。让"大工程"变成可以明天就开工的第一张工单。

## 何时使用

- 项目超过 3 天工作量，或涉及多个环节
- 方案已定，需要变成排期
- 团队协作前分配任务

## 工作流

### 第 1 步：目标一句话 + 完成定义
"做成什么样算完"写成可检查的验收句（不是"上线"而是"X 月 X 日前，用户能完成 A→B→C 全流程，成功率 ≥ 99%"）。

### 第 2 步：拆到"一两天"粒度
每个工单满足：
- 一人 1-2 天能做完（超了继续拆）
- 完成标准可验证（能跑通什么/测试通过什么）
- 有明确产出物

### 第 3 步：画依赖，找关键路径
- 谁阻塞谁：连线表达依赖，虚线表达"最好先后但不强制"
- **关键路径**：最长依赖链，决定总工期。关键路径上的工单优先排、优先保
- 能并行的明确标出并行组

### 第 4 步：排期与缓冲
- 总工期 = 关键路径长度 + 15% 缓冲（经验数字，拍脑袋除外）
- 第一个可开工工单单独点名："现在就能干的是这张"

## 质量检查

- [ ] 每个工单有负责人位、工时估、验收标准三项
- [ ] 关键路径已标出且占总工时直觉合理
- [ ] 没有不可验证的工单（"优化体验"这种必须拆成可测项）
- [ ] 第一张可开工工单已点名

## 输出格式

依赖图（文字/图示）→ 工单表（编号/标题/依赖/工时/验收）→ 关键路径与总工期 → 今日可开工项。
