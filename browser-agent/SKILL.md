# Browser Agent · 浏览器智能体

任务 → 分步执行 → 留痕交付。浏览器的活，眼睛看着做完。

## 何时使用

- 需要在真实网页上查、比、填、盯、导出
- 多步骤操作链（打开→筛选→选择→确认）
- 需要定期复查的监控类任务（价格、库存、上架）

## 工作流

### 第 1 步：任务结构化
把口语任务翻译成检查表：

```
目标 ｜ 关键约束（预算/时间/条件）｜ 成功标准（拿到什么算完成）｜ 停止条件（什么情况放弃并报告）
```

示例："下周二 北京→上海 最便宜直飞" → 目标：找最低价直飞；成功标准：给出航班号+价格+链接；停止条件：无直飞则报告最优中转。

### 第 2 步：分步执行，每步留痕
1. 每个动作（打开/输入/点击/等待）记录一步日志
2. 页面结构每次操作后重新读取，不凭上一步记忆盲点
3. 遇到验证码/登录墙/异常弹窗：停下来报告，不硬闯

### 第 3 步：结果交叉验证
关键数字（价格/日期/数量）在同一页面两个位置核对，或刷新后复读。**报错数据的浏览器智能体不如不报。**

### 第 4 步：交付物
- 结论一句话置顶
- 证据列表：每条带来源与截图/快照时间
- 监控类任务附"下次复查时间"

## 质量检查

- [ ] 每个关键数字都有来源佐证
- [ ] 没有对未加载完成的元素做操作
- [ ] 失败/中断如实报告，不粉饰成"已完成"
- [ ] 交付里有停止条件触发的说明（如触发）

## 输出格式

结论 + 证据 + 后续动作（若有）。用户只要结论时给一句话，证据折叠附后。
